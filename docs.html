1. Executive Overview & System Architecture

1.1 Product Intent

Time is a lightweight, high-performance desktop web browser designed with a minimalist aesthetic and strict window management protocols. Version 1.0 focuses on core browsing capabilities, keyboard-first navigation, tab isolation, and low-overhead local state persistence.

The architecture follows a dual-phase delivery model:

  1. Phase 1 (Web Prototype): Pure DOM/Browser-compatible implementation built using HTML5, CSS3 (Modern Flexbox/Grid + Custom Properties), and Vanilla ES6+ JavaScript.
  2. Phase 2 (Desktop Packaging): Integration with Electron, isolating renderer UI from Node.js runtime while exposing system capabilities via IPC bridges and contextBridge.

3. Feature Requirements & Technical Implementation

3.1 Tab Management Engine

Overview

The tab manager coordinates tab state creation, destruction, activation, reordering, and view switching.

Functional Requirements

  • Tab Creation: Clicking the + button or pressing Cmd + T spawns a new tab targeting the default start page (time://newtab).
  • Active State Enforcement: Only one tab may hold active focus at a time. Activating a tab updates the DOM class structure, hides all inactive viewports, displays the target viewport, and populates the Omnibox with the active tab's URL.
  • Tab Closure: Clicking the x button on a tab or pressing Cmd + W destroys the corresponding viewport and tab DOM elements.
  • Edge Case: Closing the active tab transfers focus to the adjacent right tab. If no right tab exists, focus moves to the adjacent left tab. Closing the last remaining tab automatically opens a fresh time://newtab.
  • Reordering: Drag-and-drop interface powered by HTML5 Drag and Drop API or PointerEvents. Reordering modifies the underlying internal array model and re-indexes DOM elements without re-rendering active viewports.

Data Model (TabModel)

Technical Parsing Logic

JAVASCRIPT
function parseOmniboxInput(input, defaultEngine = 'https://duckduckgo.com/?q=') {
 const trimmed = input.trim();

 // 1. Internal protocol check
 if (trimmed.startsWith('time://')) {
 return trimmed;
  }

 // 2. URL Regex check
 const urlPattern = /^(https?:\/\/)?([\\w.-]+)\.([a-z]{2,})(:\\d{1,5})?(\/.*)?$/i;
 const localhostPattern = /^(https?:\/\/)?(localhost|127\.0\.0\.1)(:\\d{1,5})?(\/.*)?$/i;

 if (urlPattern.test(trimmed) || localhostPattern.test(trimmed)) {
 return /^https?:\/\//i.test(trimmed) ? trimmed : `https://${trimmed}`;
  }

 // 3. Fallback to Search Query
 return `${defaultEngine}${encodeURIComponent(trimmed)}`;
}

3.3 History & Bookmarks Persistence System

Overview

All browser data persists locally in IndexedDB to ensure fast lookups, low memory usage, and zero cloud dependencies.

Storage Schema Definition

JAVASCRIPT
const DB_NAME = 'TimeBrowserDB';
const DB_VERSION = 1;

function initDatabase() {
 return new Promise((resolve, reject) => {
 const request = indexedDB.open(DB_NAME, DB_VERSION);

    request.onupgradeneeded = (event) => {
 const db = event.target.result;

 // History Store
 if (!db.objectStoreNames.contains('history')) {
 const historyStore = db.createObjectStore('history', { keyPath: 'id', autoIncrement: true });
        historyStore.createIndex('url', 'url', { unique: false });
        historyStore.createIndex('timestamp', 'timestamp', { unique: false });
      }

 // Bookmarks Store
 if (!db.objectStoreNames.contains('bookmarks')) {
 const bookmarkStore = db.createObjectStore('bookmarks', { keyPath: 'url' });
        bookmarkStore.createIndex('title', 'title', { unique: false });
        bookmarkStore.createIndex('createdAt', 'createdAt', { unique: false });
      }
    };

    request.onsuccess = () => resolve(request.result);
    request.onerror = (err) => reject(err);
  });
}

3.4.8 Edge Cases & Defensive Engineering

  1. Network Disconnection during Weather Fetch:
    * Failure Mode: Network fetch times out after 3000ms.
    * Mitigation: Silently catch fetch promise rejection, preserve UI layout without layout shift, render last cached weather payload with a offline status icon.
  2. Unusually Long User Name or Bookmarks Titles:
    * Failure Mode: Text overflow breaks CSS Grid structure or causes horizontal scrollbars.
    * Mitigation: Apply strict CSS truncation (white-space: nowrap; overflow: hidden; text-overflow: ellipsis;) with explicit max-width tokens on all variable text containers.
  3. Rapid New Tab Creation (Cmd + T Spammers):
    * Failure Mode: Multiple concurrent IndexedDB database reads cause UI thread stutter or race conditions.
    * Mitigation: Cache initial Home Dashboard state in memory within the background Electron process; instantly pass pre-rendered DOM template payload via IPC bridge.
  4. Low Screen Resolution / High OS Scaling (e.g., 1280x720 at 150% scaling):
    * Failure Mode: Vertical overflow requires scrolling, hiding primary search tools.
    * Mitigation: Automatically drop vertical spacing scale variables (--tb-space-5 reduces to --tb-space-2) via CSS container queries when viewport height is <700px.

3.5 Core Browser Functionality Specification

3.5.1 System Purpose & Core Architecture

The Core Browser Functionality governs all fundamental user agent operations within Time Browser. Designed around an Isolated Viewport Model, the browser shell decouples window management, address bar routing, and session state from the actual web page rendering contexts. This ensures that web page script freezes or memory leaks never lock up the browser's user interface.

3.5.2 Functional Requirements

1. Tab Management Engine

  • Tab Lifecycle States: Unloaded → Loading → Active → Inactive → Hibernated.
  • Tab Creation & Switching:
  • New tabs launch instantly (< 16ms thread response) using pre-cached DOM shells.
  • Cmd + T: Spawns a new tab adjacent to the current active tab.
  • Cmd + W: Closes active tab; shifts focus to the immediate right tab (or left tab if closing the rightmost tab).
  • Cmd + Shift + T: Reopens the last closed tab in its exact historical scroll position and session state.
  • Tab Hibernation & Memory Discarding:
  • Inactive tabs exceeding 20 minutes of zero user interaction are automatically candidate-evaluated for hibernation.
  • Hibernated tabs retain their tab strip title, favicon, and URL state in IndexedDB while releasing their active rendering process from system RAM. Clicking a hibernated tab restores its state seamlessly.

2. Omnibox Address Bar & Routing Engine

  • Dual-Function Input: Accepts both explicit URLs (https://..., localhost:3000) and arbitrary search strings.
  • Input Sanitization & Protocol Injection:
  • If no scheme is provided, inputs matching domain structures (domain.com, 192.168.1.1) default to https://.
  • All non-URL strings route directly to the user's default configured search engine.
  • Inline Domain Highlighting: The Omnibox visually dims paths and query parameters, highlighting the primary registered domain (e.g., github.com/time-browser/engine) for instant phishing identification.

3. Search & Real-Time Suggestions

  • Fuzzy-Matching Engine: Performs real-time local search across local bookmarks, open tab titles, and local history logs.
  • Debounced Remote Suggestions: Remote search suggestions fetch via debounced JSON calls (100ms debounce delay) with zero personal telemetry attached.
  • Privacy Mode Query Routing: Option to strip search query tracking tokens (utm_*, gclid) upon navigation dispatch.

4. Navigation & Page Refresh

  • Navigation Stack: Dedicated forward/backward history stack per tab process.
  • Action Handlers:
  • Cmd + [ / Back Button: Navigates to previous page in history stack.
  • Cmd + ] / Forward Button: Navigates to next page in history stack.
  • Cmd + R / Reload Button: Standard cached page refresh.
  • Cmd + Shift + R: Hard refresh (bypasses local HTTP web cache and clears page service worker).

5. History & Local Activity Trajectory

  • Data Model: Fully local, privacy-centric IndexedDB history storage. No cloud syncing.
  • Retention Control: Default retention set to 90 days; customizable to auto-purge on exit.
  • Searchability: Full-text indexing on page titles, URLs, and visit timestamps.

6. Downloads Manager Engine

  • Download Lifecycle: Handles file streams via Electron IPC bridge directly to local storage.
  • Security Scanning: Integrated local file extension validation (warns on .exe, .dmg, .sh, .bat downloads).
  • Controls: Pause, resume, cancel, reveal in Finder/Explorer, and clear download record.

7. Bookmarks System

  • Storage Hierarchy: Root Bookmarks Bar, Custom Folders, and Pinned Quick Access Slots.
  • One-Click Action: Clicking the Bookmark Star icon in the Omnibox instantly toggles bookmark status for the current URL.

8. Loading States & Page Feedback

  • Progress Tracking: Page load progress monitored via webview event hooks (did-start-loading, did-stop-loading, page-title-updated).
  • Visual Indicators: Top 2px high-performance progress line across the active tab bottom edge; favicons swap to a subtle loading spinner during navigation.

9. Custom Context Menus

  • Context Sensitivity: Custom glassmorphism context menus override default OS menus for web viewports, tab headers, address bars, and links.
  • Link Options: Open Link in New Tab, Open in New Window, Copy Link Address, Inspect Element.

10. Native Error Pages (time://error)

  • Deterministic Fallbacks: Custom, clean error surfaces for common network and protocol failures:
  • ERR_INTERNET_DISCONNECTED: Network drop fallback.
  • ERR_NAME_NOT_RESOLVED: DNS lookup failure.
  • ERR_SSL_PROTOCOL_ERROR: Security certificate mismatch.
  • One-Click Interventions: Quick "Try Again" button, local DNS cache flush trigger, and system proxy check shortcut.

3.5.5 Security & Isolation Protocols

  1. Process Isolation: Every tab runs inside its own sandbox process (contextIsolation: true, nodeIntegration: false). A crash in one tab process cannot compromise the browser shell or other open tabs.
  2. HTTPS First & HSTS Enforcement: All HTTP requests automatically upgrade to HTTPS. Non-HTTPS connections trigger an explicit security warning badge in the Omnibox.
  3. Strict IPC Whitelisting: Render processes communicate with the main Electron process strictly through a predefined, sanitized IPC bridge channel (window.timeApi). No arbitrary Node.js execution is permitted from web contexts.

3.5.6 Future Architectural Support (Roadmap)

  • Custom Extension Runtime (v2.0): Native Chrome Extension API compatibility wrapper (chrome.tabs, chrome.webRequest) operating within isolated worker sandboxes.
  • Multi-Profile Workspaces (v1.5): Isolated cookie and local storage containers per tab group, allowing concurrent logins to the same service across different workspaces.
  • Native Ad & Tracker Blocking (v1.5): Rust-backed network request interceptor evaluating network calls against blocklists in sub-millisecond execution windows.

3.16 Downloads Manager (time://downloads) Specification

3.16.1 System Architecture & Transfer Pipeline

The Downloads Manager provides real-time visibility and granular control over all network file transfers (HTTP/HTTPS, WebRTC streams, and local blobs). Integrated directly into the browser core, it operates as a full-tab manager (time://downloads) and as a quick popover drawer accessible via the top navigation bar or keyboard shortcut (Cmd + Shift + J).

+-----------------------------------------------------------------------------------+
|  NETWORK TRANSFER PIPELINE                                                        |
|                                                                                   |
|  [ Remote URL ] ---> [ Chunked Stream Fetcher ] ---> [ Temporary Disk Buffer ]    |
|                             |                                  |                  |
|                             v                                  v                  |
|                     [ Speed/ETA Engine ]              [ Integrity Verifier ]      |
|                                                                |                  |
|                                                                v                  |
|                                                     [ Destination Directory ]     |
+-----------------------------------------------------------------------------------+

Storage & State Core

  1. Transfer Buffer Store: Streams incoming byte chunks to a temporary staging file (.part / .crdownload) on the local disk before finalizing execution to prevent corrupt incomplete files.
  2. Metadata Store (IndexedDB): Maintains state records for active, paused, completed, and failed downloads, including byte totals, MIME types, source URLs, and file paths.
  3. Chunked Resumption Engine: Utilizes HTTP Range headers (Range: bytes=X-Y) to pause and resume multi-gigabyte transfers seamlessly without restarting from zero.

3.16.2 Functional Specifications

1. Transfer Controls & Lifecycle Engine

  • Pause (II): Suspends the active TCP connection stream, preserving the downloaded chunk offset in the local staging buffer.
  • Resume (▶): Issues a request with Range: bytes=[downloaded_bytes]- to continue streaming from the exact interruption byte.
  • Cancel (✖): Immediately terminates active socket connections, cleans up the temporary disk staging buffer, and updates status to Cancelled.
  • Retry (↻): Re-initiates failed or cancelled transfers from the original URL source.

2. Search & Filtering System

  • Real-time Search Bar: Filters transfers dynamically across file names, file extensions, source domains, and target paths.
  • Category Filters: Quick toggle chips to inspect specific file types:
  • 📁 All Downloads
  • 📄 Documents (.pdf, .docx, .txt)
  • 🖼️ Media (.png, .jpg, .mp4, .mkv)
  • 📦 Archives & Code (.zip, .tar.gz, .iso, .dmg)
  • ⚠️ Failed / Interrupted

3. Sorting Engine

Sort transfer items by:

  • Date Added: Newest First (Default) / Oldest First.
  • File Size: Largest First / Smallest First.
  • Transfer Speed: Active Fast Transfers First.
  • Alphabetical: A–Z / Z–A (by File Name).

4. Transfer History & Storage Analytics

  • Historical Registry: Retains past download records with single-click options to "Show in Folder" (opens native OS file explorer) or "Delete Record".
  • Storage Footprint Tracker: Top banner displaying available disk space on the primary storage volume alongside total space consumed by downloaded items.
  • Auto-Cleanup Rules: Optional setting to auto-purge download history records or move temporary files older than 30 days to the system trash.

Appendix A: Technical Glossary

  • ASAR (Atom Shell Archive Format): An uncompressed tar-like archive format used by Electron to package application source code into a single container while preserving fast read access.
  • CRDT (Conflict-free Replicated Data Type): A data structure replicated across multiple computers in a network that can be updated independently and concurrently without coordination, guaranteeing convergence without conflict.
  • E2EE (End-to-End Encryption): A system of communication where only the communicating users can read the messages, preventing third parties or cloud servers from accessing cryptographic keys.
  • IPC (Inter-Process Communication): The set of mechanisms used by the main process and renderer processes in Electron to exchange structured data safely.
  • Manifest V3 (MV3): The current browser extension API platform emphasizing enhanced security, privacy, and performance by replacing background pages with ephemeral service workers.
  • Preload Script: A script executed before renderer code is loaded in Electron that has access to Node.js/native APIs and exposes a sanitized surface to the window object via contextBridge.
  • SLM (Small Language Model): Highly optimized, localized generative AI models designed to run efficiently on client hardware (e.g., via WebGPU) without cloud round-trips.
  • WebGPU: A modern web API providing low-level, high-performance GPU acceleration for graphics rendering and general-purpose parallel computing directly in the browser renderer.

Appendix E: Coding & Architecture Standards

1. TypeScript & Type Safety

  • Enable strict mode ("strict": true) across all tsconfig.json configurations.
  • Explicit return types are required on all exported functions and public API handlers.
  • Never use any; use unknown accompanied by type guards or schema parsers (Zod).

2. Process Boundaries & IPC Safety

  • Rule of Isolation: The renderer process must never import Node.js core modules directly.
  • Bridge Surface: All communication across the bridge must pass through contextBridge.exposeInMainWorld.
  • Zero-Trust Input: Treat all incoming IPC messages as untrusted third-party HTTP requests. Validate using strict schema validation:
JAVASCRIPT
// Main Process IPC Bridge Handler Example
import { ipcMain } from 'electron';
import { z } from 'zod';

const CreateTabSchema = z.object({
  url: z.string().url(),
  active: z.boolean().default(true),
});

ipcMain.handle('tab:create', async (event, rawPayload) => {
 // Validate incoming payload from untrusted renderer
 const result = CreateTabSchema.safeParse(rawPayload);
 if (!result.success) {
 throw new Error(`Invalid IPC Payload: ${result.error.message}`);
  }

 return await TabManager.createTab(result.data);
});
